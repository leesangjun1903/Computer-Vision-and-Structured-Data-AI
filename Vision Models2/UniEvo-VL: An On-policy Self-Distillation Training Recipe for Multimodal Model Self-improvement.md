## 1. Executive summary

UniEvo-VL의 목적은 생성한 이미지의 오류를 점검하고 수정한 경험을 모델에 학습시켜, 이후에는 **추가 수정 지시 없이 원래 요청만으로 더 나은 이미지를 생성**하게 하는 것입니다〔pp.2–5, Figure 2〕.  
핵심 방법은 수정된 요청을 받는 교사와 원래 요청만 받는 학생이 **학생의 동일한 생성 중간 상태에서 내놓는 예측을 일치시키는 것**이며, 수정 완료 이미지를 정답으로 학습하거나 평가 점수를 보상으로 최적화하지 않습니다〔pp.4–5, 식 3; p.13, 식 6–7〕. 2609.38721v1  
실제 구현에서는 Qwen-Image-2512 생성기의 소규모 추가 가중치만 학습하고, 이미지 비평 및 요청문 재작성 모델은 고정하므로, 하나의 네트워크가 이해와 생성을 함께 발전시킨 실험으로 해석해서는 안 됩니다〔p.13, Appendix A〕. 2609.38721v1  
수정 후 검증을 사용하는 설정의 대응 비교에서 직접 생성 점수는 GenEval **0.748→0.818**, GenEval2 **31.92→35.07**, 이미지 내 문자 재현 과제 **0.769→0.790**으로 향상되었습니다〔p.8, Table 2〕.  
학습 후에도 추가 비평을 한 번 허용하면 세 점수는 각각 **0.848, 46.23, 0.803**으로 높아져, 학습된 개선과 추론 중 수정이 상호보완적임을 보여줍니다〔p.8, Table 2〕. 2609.38721v1  
다만 초록의 대표 수치인 **GenEval 0.747→0.808**과 **GenEval2 32.97→35.53**은 동일한 비평기 설정의 결과가 아니며, 후자는 외부 GPT-5.6-Luna 비평기를 사용한 결과입니다〔p.6, Table 1; p.21, Table 9〕. 2609.38721v1 2609.38721v1  
또한 초기 성능이 낮은 요청에서는 큰 개선이 나타났지만 쉬운 요청에서는 소폭 퇴보했고, 문자 재현 성능은 설정에 따라 악화되기도 했습니다〔pp.6–7, Figure 4〕. 2609.38721v1  
**제 판단으로는, 이 논문은 교정 경험을 다음 생성에 축적하는 방법의 가능성을 보여주지만, 새로운 과제·도메인 전반으로의 일반화나 장기간 지속되는 자기개선까지 입증한 연구는 아닙니다**〔p.5, §3.1; p.13, Appendix A.1〕. 2609.38721v1 2609.38721v1

## 2. 연구 목적과 필요성

### 2.1 해결하려는 문제: “오류를 설명하는 능력”이 곧 “생성을 개선하는 능력”은 아니다

**[저자 보고]** 연구의 출발점은 이미지 생성 모델이 객체 수, 색상, 위치 관계 등을 잘못 표현했을 때, 시각적 이해 능력으로 그 오류를 지적할 수 있더라도 **그 설명이 생성기의 내부 예측을 어떻게 바꿔야 하는지를 직접 알려주지는 않는다**는 문제입니다.  
예를 들어 “빠진 물체를 복구하라”는 비평은 원하는 결과를 설명하지만, 생성 과정의 각 단계에서 어느 방향으로 예측을 수정할지는 지정하지 않습니다〔p.2, §1〕. 2609.38721v1

여기서 연구가 구분하는 것은 다음 두 가지입니다.

| 구분 | 무엇이 바뀌는가? | 이 논문에서의 역할 |
|---|---|---|
| 추론 중 수정 | 현재 요청에 대한 입력문 또는 출력 이미지 | 비평을 이용해 이번 이미지를 더 잘 생성 |
| 학습을 통한 개선 | 모델의 가중치 | 다음 요청에서는 비평 없이도 더 잘 생성 |

**[제 해석]** 따라서 핵심 연구 질문은 “모델이 자신의 출력을 고칠 수 있는가?”보다 좁고 구체적입니다. **“교정 지시를 받았을 때 나타나는 더 나은 생성 행동을, 교정 지시가 없는 원래 입력 조건으로 이전할 수 있는가?”**가 정확한 질문입니다〔pp.2–5〕. 2609.38721v1 2609.38721v1

> **용어 설명 — 추론과 학습:** 추론은 현재 모델로 결과를 만드는 과정이고, 학습은 이후 결과가 달라지도록 모델의 가중치를 바꾸는 과정입니다.

### 2.2 연구가 기대하는 이점과 전제

**[저자 보고]** UniEvo-VL은 별도로 학습한 고성능 이미지 생성 교사, 정답 이미지 쌍, 또는 평가 점수 기반 정책 최적화 없이 교정 경험을 학습 신호로 전환하려 합니다. 이를 뒷받침하는 가정은 **생성보다 검증이 상대적으로 쉽다**는 것입니다〔p.2, §1〕. 2609.38721v1

**[제 해석]** 이 가정은 모든 이미지·문자·공간 관계에서 성립하는 보장이 아닙니다. 비평기가 오류를 놓치거나 잘못된 수정을 제안하면 학습 신호도 잘못될 수 있습니다. 논문에서 검증 없는 문자 재현 학습이 악화되고, 비평기별 개선 양상이 달라진다는 사실은 이 전제가 **과제와 비평기의 능력에 의존함**을 보여줍니다〔p.6, Table 1; p.9, Table 3〕. 2609.38721v1 2609.38721v1

또한 “외부 감독 없이”라는 표현은 제한적으로 읽어야 합니다. **새로운 정답 이미지나 평가 보상을 요구하지 않는다는 뜻이지, 사전학습된 비평기의 지식이나 사람이 설계한 비평 지침까지 없다는 뜻은 아닙니다.** 외부 Luna 비평기 실험은 기본 Qwen 설정과 별도로 구분해야 합니다〔pp.13–16, 25–30〕. 2609.38721v1 2609.38721v1

> **용어 설명 — 감독 신호:** 모델에게 무엇을 배우라고 알려주는 정보입니다. 사람이 붙인 정답뿐 아니라, 다른 모델의 평가·수정 지시·예측도 감독 신호가 될 수 있습니다.

## 4. 모델 구조와 학습 방법

### 4.1 모델 구조: 새로운 거대 모델 설계보다는 학습 절차의 제안

**[저자 보고]** 실제 시스템은 다음과 같습니다〔pp.13–15, Appendix A; p.23, Appendix F〕. 2609.38721v1 2609.38721v1 2609.38721v1

| 구성 요소 | 실제 구현 | 학습 중 변경 여부 |
|---|---|---|
| 이미지 생성기 | Qwen-Image-2512 | 추가한 생성기 LoRA만 갱신 |
| 생성기의 기반 구성 | 기본 생성 가중치, Qwen2.5-VL 조건 인코더, VAE | 고정 |
| 학생 | 원래 요청 $p$ 를 받는 생성기 | LoRA 갱신 |
| 교사 | 수정 요청 $\tilde p$를 받는 EMA 생성기 | 학생 LoRA의 이동평균으로 갱신 |
| 비평기 | 검증 설정에서는 Qwen3-VL-8B-Thinking | 고정 |
| 요청문 재작성기 | Qwen3-VL-8B-Instruct | 고정 |

> **용어 설명 — LoRA:** 기존 모델 전체를 다시 학습하는 대신 작은 저차원 가중치 행렬을 추가해 학습하는 방식입니다.  
> **EMA:** 최근 가중치를 조금씩 반영하는 지수이동평균으로, 교사가 학생의 급격한 변화에 바로 따라가지 않도록 합니다.  
> **VAE·잠재표현:** 이미지를 압축된 수치 표현으로 바꾸고 복원하는 구성 요소와 그 압축 표현입니다. 생성 과정은 이 잠재 공간에서 진행됩니다.

**[제 해석]** 논문의 개념적 설명은 하나의 멀티모달 모델이 생성과 이해 역할을 수행하는 형태이지만, 실제 검증은 **같은 계열의 구성 요소를 연결한 생성–비평 파이프라인**입니다. 비평기는 고정되어 있으므로, 이 결과로 이해 능력과 생성 능력의 공동 향상을 주장할 수는 없습니다.

### 4.2 단계 1: 이미지를 생성하고 오류를 비평한다

**원문 식 (1), p.3**

$$
I=M_{\theta}^{\text{gen}}(p,\epsilon),
\qquad
\epsilon\sim\mathcal N(0,\mathbf I),
$$

$$
(c,a)=M_{\theta}^{\text{und}}(p,I).
$$

**기호 설명:** $p$는 원래 요청문, $\epsilon$은 초기 가우스 잡음, $\mathbf I$는 항등 공분산 행렬, $I$는 생성 이미지입니다. $M_{\theta}^{\text{gen}}$은 생성 모드, $M_{\theta}^{\text{und}}$는 이해·비평 모드를 나타냅니다. $c$는 오류와 수정 제안이며, $a\in\{0,1\}$는 수용 여부로서 $a=1$이면 수정이 필요 없다고 판정합니다. 실제 구현에서는 앞서 설명한 대로 비평 구성 요소는 고정됩니다. 2609.38721v1

이미지가 처음부터 수용되면 학습용 교정 쌍을 만들지 않고 건너뜁니다. 오류가 있고 비평이 유효한 경우만 다음 단계로 이동합니다〔p.14, Appendix A.2〕. 2609.38721v1

**[제 해석]** 이 선택은 실패 사례에 학습을 집중시키지만, 이미 잘하던 사례를 적극적으로 보존하는 신호는 줄입니다. Figure 4의 Easy 집단 퇴보와 연결해 검토해야 할 설계입니다.

### 4.3 단계 2: 비평을 독립적으로 실행 가능한 수정 요청으로 변환한다

**원문 식 (2), p.4**

$$
\tilde p=M_{\theta}^{\text{und}}(p,c).
$$

**기호 설명:** $\tilde p$는 원래 요청 $p$에 비평 $c$를 반영한 수정 요청입니다. 여기의 이해 모드 표기는 요청문 합성 기능을 나타내며, 실제 검증 설정에서는 별도의 고정된 Instruct 모델이 담당합니다. 2609.38721v1 2609.38721v1

예를 들어 “빨간 컵 두 개”라는 요청에서 컵 세 개가 생성되었다면, 수정 요청은 원래 색상과 장면을 보존하면서 “정확히 두 개”를 명시적으로 강조하도록 작성됩니다. 교사는 이전 이미지 자체가 아니라 이 **독립적인 생성 요청문**을 조건으로 사용합니다〔p.4, §2.2; p.16, Appendix B〕. 2609.38721v1 2609.38721v1

> **용어 설명 — 특권 정보:** 학습할 때 교사만 받는 추가 정보입니다. 여기서는 오류를 본 뒤 작성한 수정 요청이며, 배포 시 학생은 이를 받지 않습니다.

검증을 사용하는 경우에는 같은 초기 잡음으로 다시 생성합니다.

$$
I'=M_{\theta}^{\text{gen}}(\tilde p,\epsilon),
\qquad
(c',a')=M_{\theta}^{\text{und}}(p,I').
$$

**기호 설명:** $I'$는 수정 요청으로 재생성한 이미지, $c'$와 $a'$는 그 이미지에 대한 두 번째 비평과 수용 판정입니다. 평가는 수정 요청 $\tilde p$가 아니라 **원래 요청 $p$에 대해** 이루어집니다. 이 식은 원문 §2.2와 Algorithm 1의 절차를 정리한 것입니다. 2609.38721v1

두 번째 판정이 유효하고 $a'=1$인 경우에만 $(p,\tilde p,\epsilon)$을 학습 경험으로 채택합니다. **$I'$는 경험의 채택 여부를 정할 뿐, 다음 증류 단계의 정답 이미지가 아닙니다.**

### 4.4 단계 3: 학생이 실제로 방문하는 상태에서 교사의 예측을 학습한다

**원문 식 (3)을 표기 정리한 형태, pp.4–5**

$$
\mathcal L(\theta)=
\mathbb E_{
(p,\tilde p,\epsilon)\sim\mathcal A_k,\,
\tau\sim M_{\theta}^{\text{gen}}(p,\epsilon),\,
s_j\sim\tau
}
\left[
D\left(
M_{\theta}^{\text{gen}}(\text{sg}[s_j],p),
\text{sg}\left[
M_{\bar\theta}^{\text{gen}}(\text{sg}[s_j],\tilde p)
\right]
\right)
\right].
$$

**기호 설명:** $\mathcal A_k$는 $k$번째 반복에서 채택된 경험 집합이고, $\tau=\{s_0,\ldots,s_T\}$는 학생의 생성 궤적입니다. $s_j$는 $j$번째 잠재 상태, $\theta$와 $\bar\theta$는 학생과 교사의 매개변수, $D$는 두 국소 예측의 차이를 측정하는 함수입니다. $\text{sg}$는 해당 값으로 역전파하지 않는 연산입니다. 이 식에서 $M^{\text{gen}}(s_j,p)$는 전체 이미지 생성이 아니라 **현재 상태에서의 국소 생성 예측**을 뜻합니다. 2609.38721v1

> **용어 설명 — 온정책(on-policy):** 현재 학생 모델이 스스로 생성하며 실제로 마주치는 상태를 학습에 사용하는 방식입니다.  
> **자기 증류:** 별도의 정답 대신, 같은 모델 계열의 더 유리한 조건에서 나온 예측을 학습 대상으로 삼는 방식입니다.  
> **Stop-gradient:** 값을 목표나 입력으로 사용하되, 그 값을 만들어낸 계산 과정까지 학습 신호를 거슬러 보내지는 않는 처리입니다.

**[제 해석]** 교사가 자기 경로에서 만든 완성 이미지만 모방하는 것과 달리, 이 방법은 학생이 실제로 도달한 상태에서 “이 상태라면 수정 지시를 받은 교사는 어떻게 다음 단계를 예측하는가?”를 학습합니다. 이것이 논문의 온정책 설계가 겨냥하는 학습–추론 조건 불일치 문제입니다〔p.16, Appendix B〕. 2609.38721v1

### 4.5 실제 손실: 확률분포 KL이 아니라 결정론적 전이의 제곱오차

이 부분은 논문을 정확히 읽기 위해 특히 중요합니다.

**[저자 보고]** 본문에서는 $D$의 예로 KL·JS 발산을 언급하지만, 실제 flow 구현은 **결정론적 잠재 상태 전이의 제곱거리**를 사용하며, 부록은 이것이 정확한 확률 정책 KL·JS가 아니라고 명시합니다〔p.13, Appendix A.1〕. 2609.38721v1

> **용어 설명 — KL·JS 발산:** 두 확률분포가 얼마나 다른지 측정하는 양입니다. 여기서 실제 사용한 손실은 확률분포 자체의 비교가 아니라 두 수치 예측의 차이입니다.  
> **Flow 속도:** 현재 잠재표현을 다음 상태로 이동시키는 방향과 크기를 나타내는 벡터입니다.

먼저 조건부·무조건부 예측을 결합합니다.

**원문 식 (4), p.13**

```math
v_{\theta}^{(g)}(z,\sigma,p)
=
v_{\theta}(z,\sigma,\varnothing)
+
g\left[
v_{\theta}(z,\sigma,p)
-
v_{\theta}(z,\sigma,\varnothing)
\right],
\qquad g=4.
```

**기호 설명:** $z$는 잠재 상태, $\sigma$는 잡음 수준, $v_\theta$는 기본 속도 예측기, $\varnothing$는 빈 텍스트 조건입니다. $g$는 텍스트 조건을 강조하는 강도이며, 학생과 교사에 같은 값을 적용합니다. 2609.38721v1

> **용어 설명 — Classifier-free guidance, CFG:** 요청문이 있을 때와 없을 때의 예측 차이를 증폭해, 생성 결과가 요청을 더 강하게 따르도록 하는 방식입니다.

다음 상태의 예측은 다음과 같습니다.

**원문 식 (5), p.13**

```math
\mu_{\theta,j}(z,p)
=
z+\Delta\sigma_j\,v_{\theta}^{(g)}(z,\sigma_j,p),
\qquad
\Delta\sigma_j=\sigma_{j+1}-\sigma_j.
```

**기호 설명:** $\mu_{\theta,j}$는 학생이 예측한 다음 잠재 상태, $\sigma_j$는 $j$번째 잡음 수준, $\Delta\sigma_j$는 인접 단계 사이의 간격입니다. 나머지 기호는 앞 식과 같습니다. 2609.38721v1

학생과 교사가 **동일한 현재 상태**를 사용하므로, 전이 차이는 속도 차이로 정리됩니다.

**원문 식 (6), p.13**

```math
\begin{aligned}
\ell_j^{\text{flow}}(\theta)
&=
\frac{1}{2d}
\left\|
\mu_{\theta,j}(\text{sg}[s_j],p)
-
\text{sg}\left[
\mu_{\bar\theta,j}(\text{sg}[s_j],\tilde p)
\right]
\right\|_2^2
\\
&=
\frac{(\Delta\sigma_j)^2}{2d}
\left\|
v_{\theta}^{(g)}(\text{sg}[s_j],\sigma_j,p)
-
\text{sg}\left[
v_{\bar\theta}^{(g)}(\text{sg}[s_j],\sigma_j,\tilde p)
\right]
\right\|_2^2.
\end{aligned}
```

**기호 설명:** $d$는 잠재 벡터의 차원, $\|\cdot\|_2^2$는 각 좌표 차이의 제곱합, $\ell_j^{\text{flow}}$는 한 단계의 손실입니다. $\bar\theta$는 교사 가중치이며, 교사의 예측은 역전파하지 않는 목표로 사용됩니다. 두 번째 등식은 양쪽의 동일한 현재 상태 $s_j$가 상쇄되기 때문에 성립합니다. 2609.38721v1

**원문 식 (7), p.13**

```math
\mathcal L_{\text{flow}}(\theta)
=
\mathbb E_{(p,\tilde p,\epsilon)\sim\mathcal A_k}
\left[
\frac{1}{|\mathcal J|}
\sum_{j\in\mathcal J}
\ell_j^{\text{flow}}(\theta)
\right].
```

**기호 설명:** $\mathcal J$는 학습에 사용할 전이 단계의 집합이며, $|\mathcal J|$는 그 개수입니다. 실제 설정은 20단계 중 잡음이 가장 큰 6단계, 즉 $\mathcal J=\{0,\ldots,5\}$만 사용합니다. 따라서 모든 단계에 역전파하는 학습은 아닙니다. 2609.38721v1

교사는 실제 최적화 갱신 이후 다음 규칙으로 업데이트합니다〔p.14, Appendix A.2〕.

$$
\bar\theta
\leftarrow
\beta\bar\theta+(1-\beta)\theta,
\qquad
\beta=0.999.
$$

**기호 설명:** $\beta$는 이전 교사 가중치를 얼마나 유지할지 결정하는 계수입니다. 실제로 이동평균을 적용하는 것은 생성기 어댑터이며, 기반 생성 가중치는 공유하면서 고정합니다. 2609.38721v1

**핵심 해석:** 이 학습은 “좋은 이미지의 점수를 올린다”가 아니라, **“교정 조건에서 나온 생성기의 다음 움직임을 원래 조건의 생성기가 모방한다”**는 방식입니다. 이 차이는 보상 기반 강화학습 및 정답 이미지 기반 미세조정과 구별되는 지점입니다.

## 7. 일반화 성능: 무엇이 입증되었고 무엇이 남았는가?

> **용어 설명 — 일반화:** 학습에 사용하지 않은 사례에서도 학습한 능력을 발휘하는 것입니다. 같은 과제의 새 요청에 잘 대응하는 것과, 전혀 다른 과제·언어·스타일로 능력이 이전되는 것은 서로 다른 수준의 일반화입니다.

### 7.1 현재 근거가 지지하는 범위

**[저자 보고]** GenEval2에는 별도 구성적 학습 집합을 사용하고 800개 벤치마크 요청으로 평가하며, OCR도 학습 약 20,000개와 테스트 1,018개의 원천 집합을 설명합니다. 다만 각 과제의 생성기 LoRA는 따로 학습합니다〔pp.5, 16–17〕. 2609.38721v1 2609.38721v1

| 일반화의 수준 | 현재 증거에 대한 판단 |
|---|---|
| 수정 요청을 보지 않아도 개선이 유지되는가? | **지지됨.** 직접 생성 평가가 이를 보여준다. |
| 같은 과제의 테스트 요청에서도 향상되는가? | **제한적으로 지지됨.** 제시된 분할과 평가 결과에 근거하되, 학습 자료와 테스트의 상세한 중복 감사는 첨부본만으로 확인하기 어렵다. |
| GenEval에서 학습한 하나의 모델이 GenEval2·OCR도 개선하는가? | **입증되지 않음.** 과제별로 따로 학습했다. |
| 새로운 객체·관계 조합, 언어, 이미지 스타일에도 이전되는가? | **체계적인 평가가 제시되지 않음.** |
| 이해 능력까지 함께 좋아지는가? | **입증되지 않음.** 비평·이해 구성 요소가 고정된다. |
| 장기간 계속 학습해도 기존 능력이 보존되는가? | **입증되지 않음.** Easy 집단 퇴보와 비단조 학습 곡선이 관찰된다. |

마지막 두 판단은 학습 대상의 범위와 Figure 4·6에 근거합니다. 2609.38721v1 2609.38721v1 2609.38721v1

### 7.2 일반화 가능성을 높게 볼 수 있는 이유

**[제 해석]** 긍정적인 점은 특정 평가 점수를 직접 최적화하지 않았는데도, 별도 평가 방식인 GenEval 검출기 기반 지표에서 개선이 나타났다는 것입니다. 이는 비평에서 얻은 의미적 교정이 다른 평가 체계에도 일부 반영되었다는 근거입니다. 또한 학생의 실제 생성 상태에서 학습하므로, 고정된 정답 경로만 모방하는 방식보다 배포 시 마주치는 상태에 가까운 학습을 의도합니다〔p.16, Appendix B; pp.19–20, Appendix D.3〕. 2609.38721v1 2609.38721v1

그러나 **평가기 간 효과의 일치가 곧 도메인 밖 일반화는 아닙니다.** 동일한 벤치마크 유형의 요청을 대상으로 하는 한, 벤치마크의 어휘·구성 패턴에 특화된 개선일 가능성을 별도로 배제해야 합니다.

### 7.3 일반화를 제한할 수 있는 구조적 요인

**[제 해석]** 가장 큰 위험은 교정 내용뿐 아니라 비평기의 취향도 함께 학습된다는 점입니다. 원문은 자연광, 적당한 대비, 단순 배경 선호가 프롬프트 설계에 포함되며, 이러한 요소가 실험 개입의 일부라고 인정합니다. 따라서 “더 보기 좋은 출력”이 실제로는 **평가기나 비평기가 선호하는 좁은 스타일로 이동한 결과**일 가능성을 확인해야 합니다〔pp.21, 25〕. 2609.38721v1 2609.38721v1

또한 검증을 통과한 수정만 학습하면 신호의 정확성은 높아질 수 있지만, 현재 모델이 수정에 성공하지 못하는 가장 어려운 사례는 계속 제외될 수 있습니다. 이는 **학습 신호의 품질과 학습 범위의 다양성 사이의 상충**으로 볼 수 있습니다〔p.14, Appendix A.2〕. 2609.38721v1

### 9.1 관련 방법을 수식으로 보면 무엇이 다른가?

**[제 해석: 비교를 위한 개념식이며 각 논문의 목적함수를 그대로 복제한 식은 아닙니다.]**

온정책 증류 계열의 공통 구조는 다음처럼 정리할 수 있습니다.

```math
\mathcal L_{\text{distill}}
=
\mathbb E_{s\sim d_{\theta}}
\left[
D\bigl(
f_{\theta}(s,c_{\text{student}}),
\text{sg}[f_{\text{teacher}}(s,c_{\text{teacher}})]
\bigr)
\right].
```

**기호 설명:** $d_\theta$는 학생이 방문하는 상태의 분포, $s$는 그 상태, $f$는 다음 토큰 또는 다음 잠재 전이의 예측입니다. $c_{\text{student}}$와 $c_{\text{teacher}}$는 각 모델이 받는 조건, $D$는 해당 예측에 적합한 차이 함수입니다.

이 틀에서 GKD는 교사 자체가 별도의 지식을 제공하고, SDPO는 피드백을 추가 조건으로 사용하며, D-OPSD는 목표 이미지를, UniEvo-VL은 **자가 비평에서 합성한 수정 요청**을 사용합니다. [arXiv](https://arxiv.org/pdf/2306.13649) 2609.38721v1

따라서 UniEvo-VL의 기여를 “온정책 증류를 최초 제안했다”로 설명하면 부정확합니다. 더 적절한 평가는 **교정 경험 획득, 텍스트 특권 조건, flow 전이 증류, 학습 효과와 추론 효과의 분리 평가를 결합한 학습 절차**라는 것입니다.

### 9.2 외부 논문의 높은 숫자와 직접 순위를 매겨서는 안 된다

예를 들어 Flow-GRPO는 다른 기반 모델인 SD3.5-M에서 GenEval **0.63→0.95**를 보고합니다. 이를 UniEvo-VL의 0.808 또는 0.818과 놓고 방법의 우열로 해석하는 것은 **[직접적인 방법 비교 불가]**입니다. 기반 모델, 학습 보상, 학습 예산, 평가 이미지 및 추론 설정이 같지 않기 때문입니다. [arXiv](https://arxiv.org/abs/2505.05470) 2609.38721v1

또한 GenEval 2 원문은 기존 GenEval 평가기가 새로운 생성 모델의 출력을 제대로 평가하지 못하는 **벤치마크 드리프트**를 분석합니다. 따라서 높은 GenEval 점수 하나만으로 일반화를 평가하기보다, 새로운 조합과 독립적인 사람 평가를 함께 봐야 합니다. [arXiv](https://arxiv.org/abs/2512.16853)

> **용어 설명 — 벤치마크 드리프트:** 시간이 지나 모델의 출력 특성이 바뀌면서, 기존 자동 평가기가 사람의 판단이나 실제 능력과 점점 어긋나는 현상입니다.

### 11.2 제가 제안하는 우선순위: 일반화를 직접 검증하는 연구

#### A. “같은 과제의 개선”에서 “과제 간 이전”으로 평가를 바꿔야 한다

**[제안]** 하나의 어댑터를 GenEval 유형 자료에서만 학습한 뒤, GenEval2·문자 재현·새로운 스타일·다국어 요청을 **추가 학습 없이** 평가하는 이전 행렬을 만들 것을 권합니다.

```math
G_{a\rightarrow b}
=
S_b(\theta_a)-S_b(\theta_0).
```

**기호 설명:** $\theta_0$는 초기 모델, $\theta_a$는 과제 $a$로만 학습한 모델, $S_b$는 과제 $b$의 평가 점수입니다. $G_{a\rightarrow b}>0$이면 해당 평가에서 양의 이전, 음수이면 악화가 관찰된 것입니다. 과제마다 점수 단위가 다르므로 서로 다른 $b$의 값을 그대로 합산해서는 안 됩니다.

요청 분할 역시 단순 무작위 분할에 더해 **객체–속성–관계 조합 자체를 보류하는 분할**이 필요합니다. 그래야 익숙한 표현의 재현과 새로운 조합에 대한 일반화를 구분할 수 있습니다.

#### B. 어려운 사례 개선과 기존 능력 보존을 함께 최적화해야 한다

**[제안]** 실패 사례만 학습하기보다, 기존에 성공한 요청도 일부 재학습하거나 초기 모델의 행동을 보존하는 항을 추가할 수 있습니다.

```math
\mathcal L_{\text{proposed}}
=
\mathcal L_{\text{flow}}
+
\lambda
\mathbb E_{(s,\sigma,p)\sim\mathcal B}
\left[
\left\|
v_{\theta}^{(g)}(s,\sigma,p)
-
\text{sg}\left[
v_{\theta_0}^{(g)}(s,\sigma,p)
\right]
\right\|_2^2
\right].
```

**기호 설명:** $\mathcal B$는 보존할 기존 요청과 상태의 집합, $\theta_0$는 초기 모델의 가중치, $\lambda\geq0$는 보존 강도입니다. 나머지 기호는 앞의 flow 손실과 같습니다. **이 식은 원문의 방법이 아니라 후속 연구용 제안**이며, 보존을 강화할수록 새로운 개선을 방해할 수 있으므로 그 상충을 측정해야 합니다.

> **용어 설명 — 재생 학습:** 이전에 잘하던 사례를 다시 보여주어, 새로운 내용을 배울 때 기존 능력을 잊지 않도록 하는 방법입니다.

재귀적으로 생성한 자료를 반복 학습할 때 분포의 일부가 사라질 수 있다는 *AI models collapse when trained on recursively generated data*의 결과는 장기 다양성 검사의 필요성을 뒷받침합니다. 다만 해당 연구의 조건이 UniEvo-VL에 그대로 적용되어 반드시 붕괴한다는 뜻은 아닙니다. [Nature](https://www.nature.com/articles/s41586-024-07566-y)

#### C. 비평기의 질과 증류 목표의 질을 따로 측정해야 한다

**[제안]** 비평기의 오류 검출 정확도, 잘못된 수정 수용률, 수정 요청의 원래 의도 보존율을 사람 검증 표본으로 측정하고, 가능하면 다른 계열의 평가기로 교차 확인해야 합니다. 특히 다음 대조군이 중요합니다.

| 대조군 | 분리하려는 효과 |
|---|---|
| 원래 요청 대 단순 상세화 요청 | 실제 오류 비평의 추가 가치 |
| 올바른 비평 대 무작위로 섞은 비평 | 교정 내용의 의미적 정확성 |
| 의미 교정만 대 미적 교정 포함 | 구성 능력 향상과 스타일 편향 |
| 학생 수정 이미지 검증 대 EMA 교사 결과 검증 | 채택된 경험의 품질과 실제 교사 목표의 품질 |
| 고잡음 단계 대 저잡음 단계 대 전체 단계 | 구성 과제와 문자 과제에 적합한 학습 위치 |

이는 DiffusionOPSD가 강조한 **목표 구성의 개선과 실제 학습으로 실현된 개선의 분리**와도 연결됩니다. [arXiv](https://arxiv.org/abs/2608.24646)

#### D. 통계와 비용을 동일 조건으로 비교해야 한다

**[제안]** 여러 독립 학습 시드, 요청 단위의 대응 분석, 범주별 불확실성, 사람의 블라인드 선호 평가를 함께 보고해야 합니다. 계산 효율은 업데이트 수가 아니라 **총 생성 횟수, 비평 호출 비용, GPU 시간, 실제 지연시간**에 대해 비교하는 것이 적절합니다.

또한 같은 생성기·자료·예산에서 UniEvo-VL, 검증 이미지 기반 SFT, 보상 기반 방법, 단순 요청문 개선, 기존 온정책 증류를 비교해야 이 학습 절차의 독립적인 기여가 분명해집니다.

### 최종 판단

**UniEvo-VL의 가장 중요한 기여는 “자기 비평을 한다”는 아이디어 자체가 아니라, 비평으로 개선된 조건부 생성 행동을 원래 요청의 생성 능력으로 축적하는 구체적인 연결 방법입니다.** 직접 생성의 개선과 추가 비평의 잔여 이점을 분리해 보여준 것도 의미가 있습니다.

반면, **과제별 어댑터 개선을 범용 일반화로, 자동 선호 점수를 사람의 선호로, 짧은 학습 구간의 상승을 지속적인 재귀적 자기개선으로 확대해석해서는 안 됩니다.** 앞으로 이 연구 방향의 가치는 더 높은 단일 벤치마크 점수보다, **새 조합·새 과제·새 언어로의 이전, 기존 능력 보존, 비평 오류에 대한 견고함, 그리고 동일 비용에서의 개선**을 얼마나 입증하느냐에 달려 있다고 판단합니다.
