## 1. Executive summary — 8문장

TokenGS의 연구 목적은 입력 영상의 픽셀에 3차원 가우시안의 위치와 개수를 종속시키는 기존 설계를 바꾸어, 더 유연하고 견고한 3차원 장면 복원을 가능하게 하는 것입니다.  
이를 위해 저자들은 카메라 광선상의 깊이 대신 가우시안 중심의 3차원 좌표를 직접 예측하고, 학습 가능한 가우시안 토큰을 사용하는 인코더–디코더 구조를 제안합니다. **[저자 보고: 2–4쪽, Figure 2]** 2604.15239v1 2604.15239v1

토큰 하나가 가우시안 64개를 생성하므로 출력 개수는 입력 영상의 해상도·시점 수와 독립적으로 설정할 수 있으며, 화면 밖 가우시안에 학습 신호가 사라지는 문제는 가시성 손실로 완화합니다.  
또한 추론 시 입력 시점을 늘리거나 신경망 가중치를 고정한 채 토큰만 조정하여 추가 계산을 복원 품질 개선에 사용할 수 있습니다. **[저자 보고: 4–5쪽, 식 (1)–(2), §3.3]** 2604.15239v1 2604.15239v1

RealEstate10K에서 가장 높은 설정의 PSNR은 GS-LRM의 28.10에서 28.82로 개선되지만, 지각적 영상 차이를 측정하는 LPIPS는 0.114에서 0.130으로 오히려 나빠집니다.  
동적 장면에서도 PSNR은 BTimer보다 높지만 SSIM과 LPIPS는 낮은 성능을 보여, 저자들의 최고 성능 주장을 모든 품질 지표에서의 우위로 해석해서는 안 됩니다. **[저자 보고 및 검토: 5–6쪽, Tables 1·4]** 2604.15239v1 2604.15239v1

일반화 측면에서 확인된 성과는 주로 학습 때와 다른 입력 시점 수, 제한적인 카메라 회전 오차, 관측 범위 밖 시점, 합성 동적 장면의 중간 시각에 대한 대응입니다.  
따라서 이 논문의 가장 설득력 있는 기여는 **입력 관측량·출력 표현량·추론 시 적응을 분리한 설계**이며, 광범위한 환경 변화에 대한 일반화나 실제 3차원 기하 정확도까지 입증한 연구로 보는 것은 아직 이릅니다. **[해석: 5–8쪽, Tables 2–4, Figures 7–14]** 2604.15239v1 2604.15239v1 2604.15239v1

**용어 풀이**  
**3D Gaussian Splatting, 3DGS:** 반투명한 작은 타원체들을 모아 장면을 표현하고 영상으로 투영하는 방식.  
**토큰:** 여기서는 단어가 아니라, 신경망이 학습하는 고정 길이의 특징 벡터.  
**인코더–디코더:** 입력 정보를 특징으로 변환하는 부분과, 그 특징으로 원하는 출력을 만드는 부분.  
**PSNR·SSIM·LPIPS:** 각각 픽셀 오차, 영상 구조의 유사성, 학습된 특징 공간에서의 지각적 차이를 평가하는 지표이며, 자세한 해석은 §4에 설명합니다.

## 2. 연구의 목적과 필요성, 핵심 주장과 근거

### 2.1. 무엇을 해결하려는가?

**[저자 보고]** 기존의 픽셀 정렬 방식에는 세 가지 문제가 있습니다.  
첫째, 가우시안 중심을 카메라 광선 위의 깊이로 표현하면 잘못된 카메라 자세나 여러 영상 사이의 불일치를 내부적으로 보정하기 어렵습니다.  
둘째, 픽셀마다 가우시안을 만들면 장면의 실제 복잡도가 아니라 입력 영상 수와 해상도에 따라 표현량이 증가합니다.  
셋째, 추론 시 가우시안 속성을 직접 최적화하면 특히 입력 시점이 적을 때 학습된 장면 사전지식이 손상될 수 있습니다. **[2쪽, §1]** 2604.15239v1

**용어 풀이**  
**픽셀 정렬(pixel-aligned):** 출력되는 3차원 요소가 특정 입력 픽셀 또는 패치에 대응하도록 설계된 상태.  
**카메라 자세(pose):** 카메라의 위치와 방향.  
**학습된 사전지식(prior):** 훈련 데이터에서 익힌 “그럴듯한 장면 구조”에 대한 경향으로, 정답을 보장하는 규칙은 아닙니다.

**[해석]** 여기서 구분해야 할 것은 **“어디에 가우시안을 놓을 것인가”와 “몇 개를 만들 것인가”가 서로 다른 문제**라는 점입니다.  
좌표를 자유롭게 예측하더라도 출력 수가 픽셀 수에 묶일 수 있고, 반대로 출력 수를 줄였다고 해서 위치 제약까지 사라지는 것은 아닙니다.  
TokenGS는 두 결합을 함께 풀려는 설계입니다. **[근거: 3–4쪽, §§3.1–3.2]** 2604.15239v1 2604.15239v1

## 3. 제안 방법과 모델 구조 — 수식 및 기호 설명

### 3.1. 입력과 출력: “깊이 예측”에서 “3차원 좌표 예측”으로

**[저자 보고]** 입력은 여러 RGB 영상과 해당 카메라의 외부·내부 파라미터입니다. 출력 가우시안 하나는 다음 14개 실수 성분으로 표현됩니다. **[3쪽, §3]** 2604.15239v1

```math
g_m
=
\left(
\boldsymbol{\mu}_m,\,
\mathbf c_m,\,
\mathbf s_m,\,
\sigma_m,\,
\mathbf q_m
\right)
\in \mathbb R^{14}.
```

여기서 $m$은 가우시안 인덱스, $\boldsymbol{\mu}\_m\in\mathbb R^3$는 중심 좌표, $\mathbf c_m\in[0,1]^3$는 RGB 색, $\mathbf s_m\in\mathbb R_+^3$는 세 축의 크기, $\sigma_m\in[0,1]$는 불투명도, $\mathbf q_m$은 회전을 표현하는 4성분 단위 쿼터니언입니다.  
**이 논문의 $\sigma$는 표준편차가 아니라 불투명도**입니다.

**용어 풀이**  
**카메라 내부 파라미터:** 초점거리, 영상 중심점 등 카메라 내부의 투영 특성.  
**카메라 외부 파라미터:** 장면 좌표계에 대한 카메라 위치와 회전.  
**쿼터니언:** 3차원 회전을 수치적으로 표현하는 4개 성분의 묶음.

기존 깊이 기반 설계를 이해하기 위한 개념식은 다음과 같습니다. **아래 식은 원문에 번호가 붙은 식이 아니라, §3.1의 설명을 수식화한 것입니다.**

```math
\boldsymbol{\mu}_{i,p}
=
\mathbf o_i+d_{i,p}\mathbf r_{i,p}.
```

$\mathbf o_i$는 카메라 $i$의 중심, $\mathbf r_{i,p}$는 픽셀 $p$를 지나는 광선 방향, $d_{i,p}$는 예측 깊이입니다.  
이 표현에서는 깊이를 바꾸어도 중심이 해당 광선 위에 머뭅니다.  
TokenGS는 이 방식 대신 여러 카메라가 공유하는 좌표계에서 $\boldsymbol{\mu}_m$의 XYZ를 직접 회귀합니다. **[저자 보고: 3쪽, §3.1]** 2604.15239v1

**[해석]** 잘못된 광선에 갇히지 않도록 하는 것은 합리적인 설계 변경입니다.  
그러나 “직접 XYZ를 예측하면 카메라 오차를 반드시 복구한다”는 보장은 없습니다.  
모델은 여전히 카메라 정보를 입력받으며, 여러 영상 사이의 관계를 학습을 통해 추론해야 합니다.

### 3.2. 인코더–디코더와 학습 가능한 가우시안 토큰

<img width="1251" height="545" alt="image" src="https://github.com/user-attachments/assets/b89d1c78-ac41-452a-b1d1-cb3b3c6176f3" />

**Figure 2, 3쪽.** 왼쪽은 기본 학습, 오른쪽은 추론 시 토큰 조정입니다. 오른쪽에서 이미지 특징과 네트워크는 고정되고, 가우시안 토큰이 조정됩니다. 2604.15239v1

#### 이미지 인코딩

**[저자 보고]** 각 영상을 패치로 나누고, 영상 패치와 카메라 광선의 Plücker 좌표를 각각 선형 투영한 뒤 더합니다.  
여러 시점의 토큰은 함께 self-attention을 수행합니다. **[4쪽, §3.2.1]** 2604.15239v1 2604.15239v1

```math
N_I=\frac{N_cHW}{p^2},
\qquad
\mathbf a_{vk}
=
\text{Linear}_I(\mathbf I_{vk})
+
\text{Linear}_P(\mathbf P_{vk}),
\qquad
\mathbf B=E_\theta(\mathbf A).
```

$N_c$는 입력 시점 수, $H,W$는 영상 높이와 너비, $p$는 패치 한 변의 길이, $N_I$는 전체 영상 토큰 수입니다.  
$\mathbf I_{vk}$와 $\mathbf P_{vk}$는 시점 $v$의 $k$번째 영상 패치와 광선 좌표 패치이고, $\mathbf A$는 $\mathbf a_{vk}$를 나열한 토큰 집합입니다.  
$E_\theta$는 파라미터 $\theta$를 가진 인코더이며, $\mathbf B\in\mathbb R^{N_I\times C}$는 출력 이미지 특징입니다.

**용어 풀이**  
**패치:** 영상을 잘라 만든 작은 사각형 영역.  
**Plücker 좌표:** 3차원 직선의 방향과 위치를 표현하는 6성분 좌표로, 여기서는 픽셀의 카메라 광선을 나타냅니다.  
**Self-attention:** 같은 토큰 집합 안에서 어떤 토큰의 정보를 얼마나 참고할지 계산하는 연산.

#### 가우시안 디코딩

**[저자 보고]** 디코더는 DETR의 설계를 따르며, 학습 가능한 가우시안 토큰을 query로 사용합니다.  
디코더 블록은 이미지 특징에 대한 cross-attention, 가우시안 토큰 사이의 self-attention, 토큰별 MLP로 구성됩니다. **[4쪽, §3.2.1]** 2604.15239v1

```math
\mathbf T_{\text{out}}
=
D_\theta(\mathbf T_{\text{in}},\mathbf B),
\qquad
\mathcal G
=
h_\theta(\mathbf T_{\text{out}})
\in\mathbb R^{M\times14},
\qquad
M=N_tN_g=64N_t.
```

$\mathbf T_{\text{in}}\in\mathbb R^{N_t\times C}$는 학습 가능한 입력 가우시안 토큰, $N_t$는 토큰 수, $D_\theta$는 디코더, $h_\theta$는 최종 속성 예측 및 유효 범위 변환을 묶어 표현한 함수입니다.  
$N_g=64$는 토큰 하나가 생성하는 가우시안 수이고, $M$은 전체 가우시안 수입니다.

따라서 1,024토큰은 65,536개, 4,096토큰은 262,144개의 가우시안을 생성합니다. **이 수는 입력 시점 수나 영상 해상도와 별도로 결정됩니다.**

**용어 풀이**  
**Query·key·value:** 각각 “찾으려는 정보”, “정보를 찾기 위한 표지”, “실제로 가져올 내용”에 해당합니다.  
**Cross-attention:** 한 종류의 토큰이 다른 종류의 토큰에서 정보를 가져오는 연산.  
**MLP:** 특징을 변환하는 여러 층의 작은 신경망.

**[해석]** 토큰은 단순한 출력 자리표시자가 아니라, 여러 영상의 증거를 모아 가우시안 묶음을 생성하는 학습된 질의입니다.  
하지만 **토큰 수를 고정하는 것과 장면마다 필요한 토큰 수를 자동 결정하는 것은 다릅니다.** 원 논문은 전자를 제공합니다.

#### 계산 효율의 정확한 범위

**[저자 보고]** 모든 디코더 층에서 이미지 특징의 key–value 투영을 공유하여, 해당 저장량의 깊이 의존성을 줄입니다.  
또한 LayerScale과 QK-normalization을 사용하고, 마지막 회귀 헤드 앞의 layer normalization은 제외합니다. **[4쪽]** 2604.15239v1

**[해석]** 이것을 “입력 영상 수가 늘어도 전체 계산량이 일정하다”로 읽으면 안 됩니다.  
영상 토큰 자체는 늘어나고, 영상 간 attention과 영상–가우시안 cross-attention의 계산도 남아 있습니다.  
**고정되는 것은 출력 가우시안 수이지 전체 추론 비용이 아닙니다.**

**용어 풀이**  
**LayerScale·QK-normalization:** 각 층의 출력이나 attention 점수의 수치적 크기를 조절하여 학습을 안정화하는 장치.

### 3.3. 가시성 손실: 직접 좌표 회귀의 학습 문제를 완화

**[저자 보고]** 가우시안이 모든 감독 영상의 시야 밖에 있으면 렌더링 결과에 기여하지 못하고, 렌더링 손실로부터 좌표를 수정할 기울기를 받지 못할 수 있습니다. 저자들은 이를 *zero-gradient problem*으로 설명합니다. **[3쪽, §3.1]** 2604.15239v1

**용어 풀이**  
**기울기(gradient):** 손실을 줄이기 위해 파라미터를 어느 방향으로 바꾸어야 하는지 알려주는 학습 신호.  
**감독 영상:** 예측 결과와 비교하여 손실을 계산하는 정답 영상.

먼저 가우시안 중심을 감독 영상 $i$에 투영한 좌표를 정규화합니다.

```math
\tilde u_m^i
=
2\left(\frac{u_m^i}{W}\right)-1,
\qquad
\tilde v_m^i
=
2\left(\frac{v_m^i}{H}\right)-1.
```

$u_m^i,v_m^i$는 가우시안 $m$의 투영된 영상 좌표이고, $\tilde u_m^i,\tilde v_m^i$는 정규화 좌표입니다.  
화면 안의 점은 각 축에서 대체로 $[-1,1]$ 범위에 놓입니다. **[4쪽, 원문 식 (1)]** 2604.15239v1

가시성 손실은 다음과 같습니다.

```math
\mathcal L_{\text{vis}}
=
\sum_m
\min_{\mathbf I_i\in\mathcal I_{\text{sup}}}
\left[
\text{ReLU}\!\left(|\tilde u_m^i|-1\right)
+
\text{ReLU}\!\left(|\tilde v_m^i|-1\right)
\right].
```

$\mathcal I_{\text{sup}}$는 감독 영상 집합이고, $\text{ReLU}(x)=\max(0,x)$입니다.  
각 가우시안에 대해 **적어도 한 감독 영상의 화면 안에 들어가면 벌점이 0**이 되고, 그렇지 않으면 가장 가까운 화면 범위 쪽으로 유도합니다. 저자들은 손실을 1.0으로 clipping한다고 기술합니다. **[4쪽, 원문 식 (2)]** 2604.15239v1

**용어 풀이**  
**Clipping:** 지나치게 큰 값이나 기울기를 정해진 범위로 제한하는 것.

전체 학습 손실은 다음과 같습니다.

```math
\mathcal L
=
\mathcal L_{\text{MSE}}
+
\lambda_{\text{SSIM}}\mathcal L_{\text{SSIM}}
+
\lambda_{\text{vis}}\mathcal L_{\text{vis}},
\qquad
\lambda_{\text{SSIM}}=0.2,\quad
\lambda_{\text{vis}}=1.0.
```

$\mathcal L_{\text{MSE}}$는 렌더링 영상과 감독 영상 사이의 픽셀 평균제곱오차, $\mathcal L_{\text{SSIM}}$은 영상 구조 유사도에 기반한 손실입니다.  
위 계수는 실험 설정에 명시되어 있습니다. **[4·6쪽]** 2604.15239v1 2604.15239v1

**[해석: 중요한 한계]** 식 (2)는 엄밀한 의미의 “실제 가시성” 판정이 아니라 **투영된 중심이 화면 범위에 들어오는지에 대한 패널티**입니다.  
다른 물체에 가려졌는지, 카메라 앞쪽의 양의 깊이에 있는지 등을 이 식 자체가 명시적으로 검사하지는 않습니다.  
또한 Figure 6의 외삽 미세조정에서는 이 손실을 끕니다. 따라서 **학습 안정화와 시야 밖 장면 완성 사이에는 조절해야 할 긴장 관계**가 있습니다. **[4·6쪽, 식 (2), §4.2]** 2604.15239v1 2604.15239v1

### 3.4. 테스트 시 토큰 조정: 무엇을 바꾸고 무엇을 고정하는가?

**[저자 보고]** 추론 시에는 입력 영상 특징과 네트워크 파라미터를 고정하고 가우시안 토큰만 조정합니다. 기본 설정은 50단계, 학습률 $10^{-4}$입니다. **[5–6쪽, §3.3]** 2604.15239v1 2604.15239v1

그 절차를 이해하기 위한 개념식은 다음과 같습니다.

```math
\mathbf T^\star
=
\arg\min_{\mathbf T}
\sum_{i\in\mathcal C}
\ell\!\left(
\mathcal R\!\left(
\mathcal G_\theta(\mathbf T;\mathbf B),\pi_i
\right),
\mathbf I_i
\right),
\qquad
\theta,\mathbf B\ \text{고정}.
```

$\mathcal C$는 입력 시점 인덱스 집합, $\mathcal G_\theta$는 토큰에서 가우시안을 생성하는 고정된 모델, $\mathcal R$은 렌더러, $\pi_i$는 카메라 파라미터, $\ell$은 입력 영상에 대한 렌더링 기반 손실입니다.  
이 식은 §3.3의 절차를 정리한 것이며, 원문에 별도로 번호가 붙은 최적화 식은 아닙니다.

**용어 풀이**  
**테스트 시 최적화:** 새 장면을 처리할 때 그 장면의 입력 영상으로 일부 변수를 추가 조정하는 것.  
**렌더러:** 3차원 표현을 특정 카메라에서 본 2차원 영상으로 바꾸는 함수.

**[해석]** 신경망 가중치를 고정하면 장면 하나에 맞추느라 공유 가중치가 변하는 현상은 피할 수 있습니다.  
그러나 이것만으로 토큰의 과적합이나 잘못된 장면 생성이 불가능해지는 것은 아닙니다.  
논문이 보여주는 것은 **직접 가우시안 조정보다 유리한 기하적 편향이 나타나는 사례**이지, 사전지식 보존에 관한 이론적 보장이 아닙니다.

또한 토큰 조정의 장점을 단순히 “최적화 변수가 더 적기 때문”이라고 설명하는 것도 부정확합니다. 논문의 $C=1024$, 토큰당 가우시안 64개 설정에서는 4,096토큰의 성분 수가 **4,194,304개**, 출력 가우시안의 14성분 수가 **3,670,016개**입니다. 따라서 장점은 반드시 낮은 변수 개수가 아니라, **고정 디코더를 통해 여러 가우시안의 변화가 결합되는 방식**에서 찾아야 합니다. **[설정에 근거한 계산: 4–5쪽]** 2604.15239v1 2604.15239v1

### 3.5. 동적 장면: 정적 토큰과 시간 조건부 동적 토큰

**[저자 보고]** 토큰을 정적 집합과 동적 집합으로 나눕니다.

```math
\mathbf T^{\text S}
=
\{\mathbf T_1^{\text S},\ldots,\mathbf T_{N_s}^{\text S}\}
\in\mathbb R^{N_s\times C},
\qquad
\mathbf T^{\text D}
=
\{\mathbf T_1^{\text D},\ldots,\mathbf T_{N_d}^{\text D}\}
\in\mathbb R^{N_d\times C}.
```

$N_s,N_d$는 정적·동적 토큰 수이고, $C$는 특징 차원입니다. 동적 토큰에만 목표 시각의 임베딩을 더합니다.

```math
\tilde{\mathbf T}_j^{\text D}(t)
=
\mathbf T_j^{\text D}
+
\text{Linear}\!\left(\tau(t)\right).
```

$t$는 복원하려는 시각, $\tau(t)\in\mathbb R^{d_\tau}$는 사인·코사인 기반 시간 인코딩, $d_\tau$는 그 차원이며, $\text{Linear}$는 이를 토큰 차원 $C$로 변환하는 학습 가능한 투영입니다. **[5쪽, 원문 식 (3)–(4)]** 2604.15239v1

**용어 풀이**  
**임베딩:** 시간이나 영상 같은 입력을 신경망이 사용할 수 있는 벡터로 바꾼 표현.  
**Bullet-time:** 특정 시각의 장면 상태를 고정한 채 다양한 카메라 시점에서 보는 설정.

Figure 4의 attention 마스크는 **정적 토큰이 동적 토큰을 참조하지 않도록** 하고, 동적 토큰은 정적 토큰과 다른 동적 토큰을 참조하도록 합니다. 이는 움직이는 부분을 시간에 따라 변하지 않는 장면 구조에 조건부로 표현하도록 유도합니다. **[5쪽, Figure 4]** 2604.15239v1 2604.15239v1

**[해석]** 여기서 “causal”은 우선 **정적·동적 토큰 사이의 정보 흐름 방향**을 의미합니다. 미래 프레임을 보지 않는 온라인 시간 인과 모델이라는 뜻으로 확대하면 안 됩니다.

동일 가우시안 인덱스의 시간별 중심을 비교하면 다음과 같은 변위를 얻을 수 있습니다.

```math
\mathbf f_m(t_1,t_2)
=
\boldsymbol{\mu}_m(t_2)
-
\boldsymbol{\mu}_m(t_1).
```

$\mathbf f_m$은 가우시안 $m$의 두 시각 사이 변위입니다. 이는 Figure 9의 궤적을 이해하기 위한 식입니다.  
**좌표가 연속적으로 변하고 인덱스가 유지된다고 해서 실제 물체 표면의 동일 지점을 정확히 추적한다는 보장은 없습니다.  
**논문은 별도의 흐름 정확도 지표를 보고하지 않습니다. **[7쪽, Figures 8·9]** 2604.15239v1

## 4. 성능 향상과 한계: 지표를 분리해서 읽어야 한다

**지표 해석**  
**PSNR ↑:** 픽셀 평균제곱오차를 로그 척도로 표현한 값으로 높을수록 좋지만, 실제 기하 정확도나 사람의 선호를 직접 측정하지는 않습니다.  
**SSIM ↑:** 밝기·대비·국소 구조의 유사성을 평가합니다.  
**LPIPS ↓:** 학습된 영상 특징 사이의 차이로, 낮을수록 지각적으로 비슷하다고 평가합니다.  
**#GS:** 가우시안 수이며, 이것만으로 전체 모델 메모리나 실행 시간을 알 수는 없습니다.

4쪽에는 다음과 같이 인쇄되어 있습니다.

$$
f(x)=\text{sign}(x)\left(\exp(x)-1\right).
$$

$x$는 회귀 헤드의 실수 출력이고, $f$는 이를 좌표로 변환하는 함수입니다. 그런데 이 식을 그대로 적용하면 $x<0$에서 $\text{sign}(x)<0$이고 $\exp(x)-1<0$이므로 결과가 양수가 됩니다. 예를 들어 $f(-1)=1-e^{-1}>0$입니다. **[4쪽, §3.2.1]** 2604.15239v1

아래 비교는 **방법과 일반화 전략의 비교**입니다. 서로 다른 논문의 PSNR·속도·가우시안 감소율은 학습 데이터, 입력 수, 해상도, 사전학습, 최적화 예산이 다르므로 그대로 순위를 매기지 않았습니다. 연도는 최초 공개 시점을 기본으로 하되 후속 버전이나 학회 연도를 함께 표시했습니다.

**용어 풀이**  
**비용 볼륨(cost volume):** 여러 깊이 가정에서 영상들이 얼마나 잘 맞는지를 저장한 배열.  
**단안 깊이:** 한 장의 영상에서 추정한 거리 정보.  
**점군(point cloud):** 3차원 점들의 집합.  
**빠른 가중치(fast weights):** 새로운 관측을 처리하면서 빠르게 갱신하여 일종의 기억으로 사용하는 파라미터.  
**시점 의존 외관:** 카메라 방향에 따라 달라 보이는 반사·광택 등의 현상.

**[해석]** 이 비교에서 도출되는 핵심은 다음과 같습니다. **픽셀 결합을 푸는 것, 카메라 의존성을 줄이는 것, 긴 관측을 기억하는 것, 외관을 분리하는 것은 서로 다른 일반화 문제**입니다. TokenGS는 이 중 첫 번째와 장면별 적응 인터페이스를 강하게 다루지만, 나머지를 모두 해결한 모델은 아닙니다.

또한 SparseSplat·tttLRM 등은 TokenGS와 동시대이거나 먼저 공개된 연구입니다. 이들을 **TokenGS가 실제로 영향을 주어 나온 후속 연구라고 단정하지 않았습니다.**

## 10. 결론과 후속 연구 방향

### 10.1. 저자들이 제시한 시사점과 계획

**[저자 보고]** 저자들은 직접 중심 좌표를 회귀하고 가우시안 토큰을 사용하는 설계가 견고성, 기하 품질, 동적 모델링, 테스트 시 확장에 유리하다고 결론짓습니다. 동시에 대규모 환경과 미세 기하의 어려움, 수십 단계가 필요한 토큰 조정 비용을 인정합니다. 명시적인 후속 방향은 **토큰 조정과 가우시안 직접 조정을 결합하는 하이브리드 최적화**입니다. **[8쪽, §5 및 Figure 12 인근 설명]** 2604.15239v1 2604.15239v1

### 10.2. 추가 후속 연구 제안 — 일반화 향상을 중심으로

#### A. 카메라·좌표계·장면 스케일 변화에 대한 일반화부터 분리 검증해야 한다

**[제안]** 회전 오차뿐 아니라 이동, 초점거리, 시야각, 장면 스케일을 독립적으로 변화시키는 평가가 우선입니다. 학습에서는 좌표계와 스케일 변환에 대해 일관된 예측을 유도하고, 필요하면 VGGT·AnySplat 계열의 카메라 추정과 TokenGS 디코더를 결합하는 실험을 고려할 수 있습니다. 다만 추가 기하 모델이나 감독을 사용하면 원 논문의 “추가 3차원 정답 없이 학습” 조건과 구분해야 합니다. **[제안의 근거: 제한된 회전 오차 실험과 데이터별 스케일 정규화]** 2604.15239v1 2604.15239v1 [arXiv](https://arxiv.org/abs/2503.11651)

#### B. 고정 토큰 예산을 장면 복잡도에 적응하는 예산으로 확장할 가치가 있다

**[제안]** 복잡한 영역에는 토큰을 추가하고 단순하거나 중복된 영역에서는 줄이는 계층적 구조가 유망합니다. SparseSplat의 정보량 기반 배치와 TokenGS의 학습 질의를 결합하면, 출력 수를 단순히 고정하는 것을 넘어 **같은 표현 예산으로 낯선 장면의 복잡도에 적응하는 능력**을 시험할 수 있습니다. 성공 여부는 가우시안 수만이 아니라 실제 메모리·렌더링 시간·기하 정확도를 함께 측정해야 합니다. [arXiv](https://arxiv.org/abs/2604.03069) 2604.15239v1

#### C. 토큰 조정에는 “사전지식 유지”와 “필요한 적응” 사이의 조절 장치가 필요하다

**[제안 — 원 논문의 식이 아님]** 가장 단순한 연구 출발점은 초기 토큰에서 지나치게 멀어지는 것을 제한하는 목적함수입니다.

```math
\mathcal L_{\text{adapt}}(\mathbf T)
=
\mathcal L_{\text{input}}(\mathbf T)
+
\beta\|\mathbf T-\mathbf T_0\|_F^2.
```

$\mathbf T_0$는 초기 토큰, $\mathbf T$는 조정 중인 토큰, $\mathcal L_{\text{input}}$은 입력 영상 적합 손실, $\|\cdot\|_F$는 행렬 성분 전체의 제곱합에 기반한 노름, $\beta\ge0$는 변화 제한의 강도입니다.

이 식은 일반화 개선을 보장하지 않습니다. 새로운 장면이 훈련 분포에서 멀다면 큰 변화가 필요할 수 있으므로, $\beta$나 조정 범위를 관측 신뢰도에 따라 바꾸는 방향을 검증해야 합니다. TTT3R의 신뢰도 기반 갱신, ReSplat의 학습된 반복 개선은 이런 설계를 비교할 유용한 참고점입니다. [arXiv](https://arxiv.org/abs/2509.26645)

#### D. 기하·외관·동작의 정확도를 분리해 개선해야 한다

**[제안]** TokenGS의 반복적인 LPIPS 열세를 고려하면, 위치 표현의 개선과 외관 표현의 개선을 분리하는 실험이 필요합니다. 예를 들어 시점 의존 색을 표현하는 모듈을 추가하되, 그 결과가 잘못된 기하를 색으로 가리는 방향으로 작동하지 않는지 검증해야 합니다. AESplat의 외관 분리는 관련 아이디어지만, TokenGS에 적용했을 때의 이득은 아직 가설입니다. 동적 모델에는 영상 품질뿐 아니라 실제 3차원 추적 정확도를 별도 평가해야 합니다. [arXiv](https://arxiv.org/abs/2609.36693) 2604.15239v1 2604.15239v1

#### E. 후속 논문에서는 평가 설계 자체를 강화해야 한다

**[제안]** 입력 시점과 평가 시점을 완전히 분리하고, 외삽 거리에 따른 성능 저하를 보고하며, 여러 학습 seed와 **장면 단위 paired bootstrap 신뢰구간**을 제시하는 것이 바람직합니다. 또한 같은 출력 수, 같은 학습 예산, 같은 추가 추론 시간에서 비교해야 “토큰 구조가 일반화를 개선했다”는 결론을 더 강하게 뒷받침할 수 있습니다.

**용어 풀이**  
**Paired bootstrap:** 동일한 장면에서 얻은 두 모델의 결과 쌍을 함께 재표집하여 평균 성능 차이의 불확실성을 추정하는 방법. 같은 장면의 여러 영상은 서로 관련되어 있으므로, 여기서는 장면 단위로 평가하는 것이 중요합니다.

### 최종 판단

**TokenGS는 “3차원 표현을 입력 픽셀의 부속물로 만들 필요가 없다”는 설계 관점을 설득력 있게 보여주는 논문입니다.** 특히 입력 수 변화에 대한 대응과 장면별 적응 인터페이스는 후속 연구 가치가 큽니다. 다만 현재 증거가 가장 강하게 지지하는 것은 **표현과 최적화의 유연성**이며, **보편적인 영상 품질 우위·정확한 실제 기하·광범위한 분포 밖 일반화**는 별도로 검증해야 할 주장입니다. 2604.15239v1
