# Do As I Can, Not As I Say: Grounding Language in Robotic Affordances

### 1. 핵심 주장 및 주요 기여

이 논문은 **대규모 언어 모델(LLM)이 로봇에 물리적 실감을 가지지 못한다는 근본적인 문제**를 해결하고자 제시되었습니다. 핵심 주장은 LLM의 의미론적 지식과 로봇 어포던스(affordances)의 실행 가능성을 결합함으로써, 로봇이 자연 언어 지시사항을 복잡하고 장기적인 조작 작업으로 실행할 수 있다는 것입니다.[1]

**주요 기여**는 다음과 같습니다:

- **SayCan 알고리즘**: LLM의 확률과 로봇 스킬의 어포던스 함수를 곱셈으로 결합하여 실행 가능하면서도 맥락 적절한 행동을 선택하는 방법론 제시[1]
- **실제 로봇 평가**: 모바일 매니퓰레이터를 이용한 101개의 실제 로봇 작업에서 84% 계획 성공률, 74% 실행 성공률 달성[1]
- **LLM 개선과의 직접 연계**: 모델 크기 개선(FLAN에서 PaLM으로)이 로봇 성능 향상으로 직접 이어짐을 입증하는 첫 사례 제시[1]

***

### 2. 문제 정의 및 해결 방법론

#### 2.1 해결하고자 하는 문제

LLM은 대규모 텍스트에서 학습한 풍부한 의미론적 지식을 보유하지만, 실제 환경과의 상호작용 경험이 없어 다음과 같은 문제가 발생합니다:[1]

- LLM이 제안하는 행동이 로봇의 물리적 능력 범위를 벗어날 수 있음 (예: 환경에 없는 청소기 사용 제안)
- 현재 환경 상태와 무관하게 불가능한 행동을 생성할 수 있음
- 로봇의 구체적인 스킬 세트를 인식하지 못함

#### 2.2 제안하는 방법론

**SayCan의 핵심 수식**은 다음과 같습니다:[1]

$$p(c_i|i, s, \ell_{\pi}) \propto p(c_{\pi}|s, \ell_{\pi}) \cdot p(\ell_{\pi}|i)$$

여기서:
- $p(c_i|i, s, \ell_{\pi})$: 지시사항 $i$를 진행하는 스킬의 확률
- $p(c_{\pi}|s, \ell_{\pi})$: **세계-접지** (world-grounding) - 현재 상태 $s$에서 스킬 $\ell_{\pi}$가 성공할 확률 (어포던스 함수)
- $p(\ell_{\pi}|i)$: **작업-접지** (task-grounding) - LLM이 스킬 $\ell_{\pi}$가 지시사항 $i$에 도움이 될 확률

이 인수분해는 다음과 같은 직관을 기반으로 합니다:[1]
- 성공한 스킬은 지시사항 진행 확률 = $p(\ell_{\pi}|i)$
- 실패한 스킬은 지시사항 진행 확률 = 0

#### 2.3 LLM 활용 방식

기존 생성 기반 접근과 달리, SayCan은 **스코링 모드**를 활용합니다:[1]

고정된 스킬 집합 $\{\ell_{\pi}\}$에 대해 다음을 계산합니다:

$$\ell_{\pi}^* = \arg\max_{\ell_{\pi} \in \ell_{\Pi}} p(\ell_{\pi}|i)$$

이를 통해 LLM의 출력을 로봇 스킬로 제약하면서도 LLM의 의미론적 지식을 활용합니다.

### 3. 상세 모델 구조

#### 3.1 전체 알고리즘

**Algorithm 1: SayCan**[1]

```
입력: 고수준 지시사항 i, 초기 상태 s₀, 스킬 집합 Π와 그 설명 ℓ_Π

1: n = 0, π = ∅
2: while ℓ_{π_{n-1}} ≠ "done" do
3:    C = ∅
4:    for π ∈ Π and ℓ_π ∈ ℓ_Π do
5:       p^LLM_π = p(ℓ_π|i, ℓ_{π_{n-1}}, ..., ℓ_{π_0})  // LLM 스코어
6:       p^affordance_π = p(c_π|s_n, ℓ_π)              // 어포던스 함수
7:       p^combined_π = p^affordance_π · p^LLM_π       // 결합 확률
8:       C = C ∪ p^combined_π
9:    end for
10:   π_n = arg max_{π∈Π} C                            // 최적 스킬 선택
11:   스킬 π_n을 환경에서 실행하여 상태 s_{n+1}로 업데이트
12:   n = n + 1
13: end while
```

#### 3.2 어포던스 함수 (Value Functions)

강화학습 기반의 Q-함수를 어포던스로 활용합니다:[1]

$$Q_{\pi}(s, a) = \mathbb{E}_{a \sim \pi(a|s)} \left[\sum_t R(s_t, a_t)\right]$$

희소 보상 (성공 시 1.0, 실패 시 0.0)을 사용하므로, Q-함수는 직접 성공 확률을 나타냅니다.[1]

**정규화된 어포던스 함수**:

- **Pick 스킬**:

$$p^{affordance}_{pick} = \text{clamp}\left(\frac{v_{pick} - v^{min}_{pick}}{v^{max}_{pick} - v^{min}_{pick}}, 0, 1\right)$$

여기서 $v^{max}\_{pick} = 0.5$, $v^{min}_{pick} = 0.2$

[1]

- **Go-to 스킬** (거리 기반):

$$p^{affordance}_{goto} = \text{clamp}\left(\frac{d^{max}_{goto} - d}{d^{max}_{goto} - d^{min}_{goto}}, 0, 1\right)$$

여기서 $d^{max}\_{goto} = 100$ m, $d^{min}_{goto} = 0$

[1]

- **Place 스킬**: $p^{affordance}_{place} = 1.0$ (언어 지시가 충분함)[1]

#### 3.3 정책 및 가치 함수 학습

**행동 복제 (BC-Z)**:[1]
- 텔레조작을 통해 수집한 68,000개의 데모
- 276,000개의 자율 에피소드로 확장
- 멀티태스크 정책: 언어 임베딩으로 조건부화
- MSE 손실함수 사용

**강화학습 (MT-Opt)**:[1]
- 시뮬레이션에서 학습 후 RetinaGAN을 통한 Sim-to-Real 전이
- 우선순위 경험 재생 사용
- 16 TPUv3 칩, ~100시간 학습
- 희소 보상 설정

**네트워크 아키텍처**:
- 입력: 640×512 RGB 이미지 + 언어 임베딩 (Universal Sentence Encoder)
- BC: ResNet-18 기반, FiLM 조건부화[1]
- RL: 7개 합성곱층 → 언어/상태 결합 → 11개 합성곱층, 시그모이드 게이팅[1]

### 4. 성능 향상 분석

#### 4.1 전체 성능

실제 주방 환경에서 101개 작업 평가:[1]

| 환경 | 계획 성공률 | 실행 성공률 |
|------|-----------|-----------|
| Mock Kitchen | 84% | 74% |
| 실제 주방 | 81% | 60% |

계획 성능 감소 3%, 실행 성능 감소 14% → 제한적인 도메인 전이[1]

#### 4.2 작업 계열별 성능

| 작업 계열 | 개수 | 계획 성공률 | 실행 성공률 |
|---------|-----|-----------|-----------|
| NL Single Primitive | 15 | 100% | 100% |
| NL Nouns (추상명사) | 15 | 67% | 47% |
| NL Verbs (추상동사) | 15 | 100% | 93% |
| Structured Language | 15 | 93% | 87% |
| Embodiment (맥락인지) | 11 | 64% | 55% |
| Crowd-Sourced | 15 | 87% | 87% |
| Long-Horizon | 15 | 73% | 47% |

**주요 관찰**:[1]
- 추상명사 작업에서 낮은 성능: 명사 선택지 15개 > 동사 선택지 6개
- Embodiment 작업에서 성능 저하: 어포던스 함수 오분류로 인한 실패
- 장기 작업의 조기 종료 문제: 65% LLM 실패, 35% 어포던스 실패[1]

#### 4.3 언어 모델 크기의 영향

| 모델 | 매개변수 | 계획 성공률 | 실행 성공률 |
|------|---------|-----------|-----------|
| PaLM (최고) | 540B | 84% | 74% |
| FLAN | 137B | 70% | 61% |
| PaLM | 62B | 82% | - |
| PaLM | 8B | 74% | - |

**결론**: 더 큰 LLM이 체계적으로 더 나은 성능을 제공 → LLM과 로봇이 협력적으로 개선될 수 있음을 시사[1]

#### 4.4 어포던스 제거 실험

| 방법 | 계획 성공률 | 실행 성공률 |
|------|-----------|-----------|
| PaLM-SayCan (완전) | 84% | 74% |
| No VF (어포던스 제거) | 67% | - |
| Generative (생성식 LLM) | 74% | - |

**영향**: 어포던스 그라운딩 제거 시 17% 계획 성능 감소[1]

### 5. 일반화 성능 향상 분석

#### 5.1 Zero-Shot 일반화

SayCan은 다음 설정에서 Zero-Shot 일반화를 달성합니다:[1]

**언어 일반화**:
- 새로운 명사 조합 (예: "bring a drink" → "bring a soda", "bring water")
- 새로운 동사 조합 (예: "restock" task family에서의 창발적 이해)
- 크라우드소싱 자연 언어 (원래 보지 못한 표현)

**신체화(Embodiment) 일반화**:
- 로봇 또는 환경 상태 변화에 대한 적응
- 어포던스는 현재 상태 $s$에 조건부이므로 동적 상황 변화 대응[1]

#### 5.2 일반화 제약 및 실패 사례

**고유한 제약**:[1]

1. **스킬 세트 의존성**: 시스템 성능이 스킬의 범위와 품질에 제한됨
   - 551개 스킬 중 평가에 사용된 스킬은 제한적
   - 새 스킬 추가 시 프롬프트 재조정 필요

2. **어포던스 오분류**: 어포던스 함수가 높은 값을 출력했으나 실패하는 경우
   - 특히 embodiment 작업에서 15% 실패율

3. **폐루프 부재**: 스킬 실패 시 피드백 메커니즘 부족
   - 외부 피드백 없이 한 번의 결정으로 실행
   - 사후 대응 불가능

4. **LLM 고유 한계 상속**: 부정(negation) 및 참조 모호성 처리 불가
   - "bring a snack that isn't an apple" 처리 불가
   - 카페인이 있는 음료 식별 불가[1]

#### 5.3 일반화 향상을 위한 방안

**Chain-of-Thought 프롬프팅**:[1]

LLM 생성 출력 → 설명 추가 → 스코어링 모드 재실행

예시:
```
사용자: "Bring me a fruit-flavored drink without caffeine"
설명: "사용자는 카페인 없는 과일맛 음료를 요청했다. 라임 소다를 가져가겠다."
로봇: 1. Find lime soda 2. Pick up lime soda 3. Bring it to you 4. Done
```

결과: 부정 처리 및 추론 기반 선택 가능[1]

**신규 스킬 통합**:
- 서랍 조작 예시: 21개 쿼리에서 100% 계획 성공률, 33% 실행 성공률[1]

**다중언어 일반화**:
- 명시적 설계 없이 영어→중국어, 프랑스어, 스페인어 전이 성공
- 계획 성공률에 거의 영향 없음[1]

### 6. 이론적 한계 및 고찰

#### 6.1 근본적 한계

**1. 스킬-수준 추상화의 경직성**[1]
- 새로운 스킬 학습 또는 기존 스킬 수정 시 어포던스 함수 재학습 필요
- 온라인 적응 어려움

**2. 어포던스 함수의 정규화 과정**[1]
- 경험적 파라미터 (예: $v^{min}\_{pick} = 0.2$, $v^{max}_{pick} = 0.5$)의 선택이 임의적
- 환경이나 스킬이 변경되면 재정의 필요

**3. LLM의 근본적 한계 상속**[1]
- 부정/참조 모호성 처리 불가
- 상식적 추론의 불완전성
- 훈련 데이터의 편향성

#### 6.2 도메인 전이 문제

Mock Kitchen → Real Kitchen 성능 감소:[1]
- 계획: 84% → 81% (3% 감소)
- 실행: 74% → 60% (14% 감소)

원인 분석:
- 어포던스 함수 재정의/재학습 부족
- 실제 환경의 시각적 변화
- 미세한 조작 정확도 문제[1]

### 7. 최신 연구 동향 및 미래 영향

#### 7.1 후속 연구

**1. Inner Monologue (2023)**
- SayCan의 폐루프 버전
- 환경 피드백을 통한 동적 재계획
- LLM이 "생각"을 통해 실패 처리[1]

**2. AutoGPT+P (2024)**[2]
- 어포던스 기반 심볼 계획 통합
- PDDL 도메인 생성으로 더 견고한 계획
- SayCan 81% 대비 **85%+ 성공률 달성**[2]

**3. RT-Affordance (2024)**[3]
- 계층적 어포던스-정책 구조
- 웹 데이터셋과 로봇 궤적 혼합 학습
- 새 작업 학습 시 추가 로봇 데이터 수집 불필요[3]

**4. RAIL - Robot Affordance Imagination (2024)**[4]
- 물리 시뮬레이터 + 생성 LLM으로 새로운 어포던스 상상
- 도메인 내 데이터 부족 시에도 새 객체 클래스에 대한 일반화[4]

**5. RoboGround (2025)**[5]
- 시각-언어 기반 접지 마스크를 정책에 전달
- 대규모 시각-언어 모델의 견고한 일반화 활용[5]

#### 7.2 연구 커뮤니티의 인정

- **인용 수**: 2,288회 인용 (2024년 11월 기준)[6]
- **주요 기여**: 로봇 공학에서 LLM 활용의 새로운 패러다임 확립[7][1]
- **벤치마크 설립**: SayCan 지시사항 집합이 새로운 평가 기준이 됨[2]

#### 7.3 향후 연구 고려사항

**1. 어포던스 표현의 다양화**[1]
- 현재: 값 함수 기반
- 미래: 시각적 어포던스 맵, 그래프 기반 표현
- 멀티모달 어포던스 (시각, 촉각, 언어 결합)

**2. 온라인 적응 메커니즘**[1]
- 실패 경험 학습
- 동적 스킬 획득
- 환경 변화에 대한 실시간 대응

**3. 진정한 Long-Horizon 추론**[1]
- 현재: 일반화된 스킬 순서 선택
- 미래: 작업 분해, 장기 계획 최적화
- 상충하는 제약 조건 처리

**4. 다중 로봇/에이전트 협업**[1]
- 분산 계획 및 실행
- 역할 기반 어포던스 함수
- 에이전트 간 커뮤니케이션

**5. 자가 개선 루프**[1]
- 로봇 경험을 활용한 LLM 파인튜닝
- 사실성과 상식적 추론 개선
- 피드백 기반 프롬프트 자동 최적화

**6. 공개 데이터셋 및 벤치마크**[7][1]
- SayCan 지시사항 세트의 표준화
- 다양한 환경/로봇 간 평가
- 재현성 강화

#### 7.4 학제 간 영향

**언어 처리와 로봇 공학의 협력**:[1]
- 로봇 피드백을 통한 LLM 개선 경로 제시

3. **확장 가능성**: LLM 개선이 직접 로봇 성능 향상으로 이어짐을 처음 보여줌[1]

4. **해석 가능성**: 자연 언어 계획으로 인간-로봇 상호작용 투명성 제공[1]

- 폐루프 적응 메커니즘 통합
